# Intelli-Edu 后端完整实施方案（从当前代码到可生产交付）

## 1. 结论与目标

项目已不是空白状态，而是处于“**业务模块基本齐全、工程化和生产就绪能力待收口**”阶段：后端为 Java 21 / Spring Boot 3.2 / Spring Cloud Alibaba 微服务，包含网关、用户、资源、课程、考试、知识、学习、AI 等域，Docker 本地环境已经覆盖 PostgreSQL、Redis、RabbitMQ、Nacos 和前端。

当前目标不是再增加服务，而是按以下顺序把它变成一套可稳定交付的智慧教育平台：

```text
P0 可运行基线与安全边界
  → P1 核心教与学闭环正确性
    → P2 异步事件与数据一致性
      → P3 质量、性能、可观测性
        → P4 AI 与生产发布
```

最终交付的最小业务闭环：教师注册/认证 → 创建课程与班级 → 发布章节资源 → 学生加入并学习 → 创建考试并提交答卷 → 生成成绩、错题和学习反馈。AI 只作为该闭环的增强能力，不能成为核心流程的单点依赖。

## 2. 当前现状盘点（2026-08-20）

### 2.1 已具备的能力

| 层面 | 当前情况 |
|---|---|
| 服务架构 | `gateway`、`user`、`resource`、`course`、`exam`、`knowledge`、`learning`、`ai` 等模块已存在；共享 DTO/Feign 位于 `Intelli-Edu-api`，通用能力位于 `Intelli-Edu-common`。 |
| 配置与发现 | 服务通过 Nacos 配置中心、注册中心运行，网关统一入口为 8890。 |
| 数据与中间件 | 本地 Compose 包含 PostgreSQL（含 pgvector）、Redis、RabbitMQ、Nacos。 |
| 业务骨架 | 已有用户认证、课程/班级/章节、资源、题库/试卷/考试/答卷、知识点、学习记录/错题/掌握度、AI 对话和课程能力的 Controller 与 Service。 |
| 本地交付 | Docker Compose 会初始化数据库和 Nacos 配置，并构建全部后端服务；前端代理到网关。 |
| 构建 | 已执行 `mvn -q -DskipTests package`，当前 Maven 全模块构建通过。 |

### 2.2 必须正视的缺口

| 优先级 | 缺口 | 风险 | 处理方向 |
|---|---|---|---|
| P0 | 11 个主要后端模块当前均无 `*Test.java` | 回归、重构、发布无安全网 | 先覆盖认证、权限、课程发布、考试提交等关键路径 |
| P0 | 部分 Feign fallback 返回 `null` | 下游异常会变成 NPE 或错误成功响应 | 统一错误语义、降级响应和调用超时 |
| P0 | 部分业务代码存在 `return null` 路径 | 空值和失败场景不透明 | 用业务异常/Optional/明确响应替代并补测试 |
| P0 | 知识点归属教师校验仍标记待办 | 可能越权修改课程知识点 | 补跨服务鉴权或资源归属快照校验 |
| P1 | 课程/考试的通知与删除同步尚为待办 | 数据最终一致性和通知不完整 | 用 RabbitMQ 事件、Outbox、幂等消费者落地 |
| P1 | 验证码实际短信/邮件发送尚为待办 | 生产登录注册流程不完整 | 抽象通知通道；本地 mock、生产真实适配 |
| P1 | 云资源、VOD、AI 等依赖依赖外部密钥 | 本地与生产行为不同，易泄露密钥 | 配置分层、Secret 管理、功能开关与降级 |
| P2 | 尚未建立 CI、质量门禁、监控告警的证据 | 无法稳定发布和排障 | 建立流水线、指标、日志、告警、Runbook |

`return null` 并不都代表缺陷（例如枚举转换的“未识别值”），但所有对外服务、Feign 降级和关键业务分支必须用测试确认其语义。

## 3. 目标架构与边界

```text
浏览器 / 管理端 / 学生端
          │
          ▼
  API Gateway：认证、限流、路由、traceId、统一错误响应
          │
 ┌────────┼──────────────────────────────────────────────┐
 ▼        ▼          ▼         ▼        ▼       ▼          ▼
用户域   课程域     资源域     考试域   知识域  学习域      AI 域
认证     班级章节   文件元数据 题库答卷  知识图 进度/错题    检索/会话
 └────────┴──────────┴─────────┴────────┴───────┴──────────┘
          │                 │
          ▼                 ▼
 PostgreSQL（按服务数据库/Schema 归属）  Redis / RabbitMQ / 对象存储
```

### 强制边界

1. `user` 是用户、角色、权限的唯一写入方；其他服务只保存用户 ID 和必要快照。
2. `course` 是课程、班级、章节的唯一写入方；`exam` 不直接查课程表。
3. `exam` 是题目、试卷、考试、答卷、成绩的唯一写入方。
4. `learning` 只消费学习事件和维护学习视图，不能反向修改考试原始答卷。
5. `resource` 管理资源元数据与访问授权；文件内容在对象存储，业务服务不转发大文件。
6. 同步查询使用定义在 `Intelli-Edu-api` 的 DTO/Feign 契约；状态传播和副作用使用 MQ 事件。

## 4. 交付路线与验收方案

每个迭代为 1～2 周。所有迭代必须包含：需求卡、API 文档、数据库变更、测试、日志/指标、演示和发布说明。

### 阶段 A：基线收口与安全底座（第 1～2 周，P0）

**目标：** 把“可构建”升级为“可安全运行、可回归验证”。

工作项：

1. 统一网关与服务的异常响应、错误码、分页、时间格式和 traceId 传递。
2. 建立认证/授权矩阵：游客、学生、教师、管理员分别可访问哪些接口与数据范围。
3. 检查网关 JWT 校验、服务端用户信息透传、Feign 传递链路；禁止仅依赖前端隐藏按钮。
4. 处理关键 `null` 分支：Feign fallback 应返回可识别的服务不可用错误；业务不存在应返回 404/业务错误而非空对象。
5. 补齐 `knowledge` 中课程教师归属校验；教师只能操作自身课程及其关联知识点。
6. 建立测试基座：JUnit 5、Spring Boot Test、Testcontainers（PG/Redis/RabbitMQ）、测试数据工厂。
7. 在 CI 中加入编译、单测、代码格式检查、依赖漏洞扫描；提交 `.env.example`，禁止提交真实密钥。

验收：

- 未登录、错误角色、跨课程越权请求均被拒绝。
- 下游服务不可用时，调用方返回规范的 5xx/业务降级错误，而不是 `null` 或 200。
- 登录、当前用户、教师建课程、学生提交答卷各有至少一条集成测试。
- 新开发环境能在 Compose 中一键启动，CI 对主分支构建和测试通过。

### 阶段 B：用户、课程、资源纵向闭环（第 3～4 周，P0）

**目标：** 交付第一条可真实使用的教学流程。

业务链路：

```text
教师登录 → 创建课程（草稿）→ 创建班级/加入学生 → 创建章节
→ 上传并关联资源 → 发布课程 → 学生查看课程 → 学习资源 → 写入进度
```

关键实现：

- 课程状态机：`DRAFT → PUBLISHED → ARCHIVED`；只允许教师或管理员变更。
- 班级成员操作要具备唯一约束和幂等性，避免重复加入。
- 上传使用预签名 URL；资源表记录所有者、用途、媒体类型、校验状态、访问范围。
- 资源访问进行课程/班级成员校验；下载链接短时有效。
- 学习进度按“用户 + 章节 + 资源”建唯一键；更新采用乐观锁或原子 SQL。
- 为课程发布、资源上传、资源访问失败、学习进度写入增加审计与指标。

验收：教师发布一门课程后，符合条件的学生可见并能完成学习；无关学生无法获得资源下载地址；同一请求重试不产生重复成员和重复进度。

### 阶段 C：测评与知识点闭环（第 5～6 周，P0）

**目标：** 保证考试数据正确、可追溯、不可被后续题目修改污染。

工作项：

1. 题库、题目与知识点关联；知识点树修改只能由课程所属教师完成。
2. 试卷发布时保存题目快照（题干、选项、答案、分值），不能只引用可变的题目 ID。
3. 考试状态机：`DRAFT → PUBLISHED → IN_PROGRESS → ENDED → ARCHIVED`。
4. 答卷状态机：`NOT_STARTED → IN_PROGRESS → SUBMITTED → GRADED`；提交使用幂等键，重复提交不重复计算分数。
5. 服务器时间作为考试时间的唯一依据；明确迟交、强制交卷、断线恢复规则。
6. 客观题可同步判分；主观题进入异步待阅流程，成绩发布有审计记录。
7. 增加并发提交、越权访问、重复请求、题目变更后的历史成绩回归测试。

验收：学生可参加其班级考试，提交后获得正确成绩；重复点击提交不会产生多份答卷；教师后来修改题目不影响已完成考试。

### 阶段 D：消息驱动的学习反馈（第 7 周，P1）

**目标：** 将跨域副作用从同步调用中解耦，构建错题与掌握度。

事件优先级：

| 事件 | 生产者 | 消费者 | 作用 |
|---|---|---|---|
| `course.published` | course | notification/learning | 通知、初始化学习视图 |
| `exam.submitted` | exam | learning | 更新错题、掌握度、学习统计 |
| `question.deleted` | exam | knowledge | 解除题目知识点关联 |
| `course.section.deleted` | course | knowledge/learning | 清理关联与学习视图 |
| `resource.ready` | resource | course/ai | 可用资源展示、资料解析 |

实现标准：

- 使用 Transactional Outbox：业务表写入和事件记录处于同一事务；后台可靠投递 MQ。
- 每个事件含 `eventId`、版本、聚合 ID、发生时间、操作者 ID。
- 消费者维护已消费事件表或幂等键；失败指数退避重试，超过阈值进入死信队列。
- 失败消息可在管理端或运维脚本中重放；不要静默丢弃。

验收：MQ 暂时不可用不丢失已提交答卷；恢复后学习画像最终完成更新；重复投递不产生重复错题记录。

### 阶段 E：AI 与外部服务治理（第 8 周，P1）

**目标：** AI 服务可控、可审计、可降级。

- 资料上传后异步提取文本、切分、向量化、写入 pgvector/Redis Vector；记录解析版本和来源。
- 问答必须基于调用者有权访问的课程资料检索，答案返回引用来源。
- 模型调用设置连接/读取超时、并发限制、用户/课程配额、成本指标和熔断降级。
- API Key 仅存在部署环境 Secret；日志中绝不输出密钥、完整提示词或敏感学生信息。
- 短信、邮件、腾讯 COS/VOD 均抽象为端口接口：本地 mock，测试 fake，生产适配器。

验收：无 AI 密钥时核心教学流程不受影响；无权限用户不能从 AI 回答获得课程资料；单个用户请求不会无限占用模型资源。

### 阶段 F：生产质量与发布（第 9～10 周，P0/P2）

1. 指标：请求 QPS、P95/P99、错误率、JVM、连接池、缓存命中、MQ 堆积、AI 调用成本。
2. 日志：JSON 结构化日志，所有入口和 Feign/MQ 链路携带 traceId。
3. 告警：服务不可用、5xx 激增、PG 连接耗尽、队列堆积、考试提交错误率、磁盘容量。
4. 压测：登录、课程列表、资源鉴权、考试开始、考试提交；输出容量结论而非只输出 TPS。
5. 安全：OWASP Top 10、越权、文件类型/大小/病毒扫描、依赖漏洞、密钥扫描。
6. 发布：镜像不可变标签、测试环境自动部署、数据库迁移预检、灰度、回滚、备份恢复演练。

验收：演练一次“错误版本发布 → 自动/手动回滚”；演练一次“数据库备份恢复”；常见告警有对应 Runbook。

## 5. API、数据与代码开发规范

### 5.1 每个接口的固定处理顺序

```text
API 契约评审
→ Request 参数校验
→ 身份和数据权限校验
→ 应用服务编排（事务边界）
→ 领域规则和持久化
→ 事件/outbox 写入
→ Response DTO
→ 审计、指标、测试
```

### 5.2 API 约定

- URL 使用资源名复数，如 `/courses/{courseId}`；动作型操作使用清晰的子资源，如 `/exams/{id}/submissions`。
- 查询接口分页统一使用 `page`、`size`、`sort`；返回总数与列表。
- 写操作使用 `@Valid`；创建返回 201，删除成功返回 204 或统一成功响应。
- 每个写操作定义幂等要求。考试提交、成员添加、MQ 消费必须幂等。
- API 版本通过 `/api/v1` 或兼容策略管理；破坏性字段变更不能直接覆盖旧客户端。

### 5.3 数据规则

- 主键建议 UUIDv7/雪花 ID；跨服务只传 ID，不传持久化实体。
- 每张业务表具有 `created_at`、`updated_at`、`created_by`、`updated_by`；软删表另有 `deleted_at`/`deleted`。
- 外键、唯一约束、非空约束在数据库层表达；索引由真实查询路径决定。
- 所有 schema 更改只通过 Flyway 迁移；生产脚本必须先在空库与升级库演练。
- 涉及成绩、考试、权限的历史数据必须保留快照和审计记录。

### 5.4 服务通信规则

- 查询：Feign + 明确超时 + Resilience4j/Sentinel + 规范 fallback。
- 命令/副作用：优先领域事件 + MQ，使用 Outbox 保证可靠投递。
- 禁止：跨库 SQL、共享 Entity、无限重试、fallback 返回 `null`、将用户请求同步串行经过多个服务。

## 6. 测试矩阵

| 场景 | 单元测试 | 集成测试 | E2E | 性能/安全 |
|---|---|---|---|---|
| 登录与 Token 刷新 | 密码、过期、签名 | Redis/JWT/安全过滤器 | 登录后访问受保护页面 | 暴力破解限流 |
| 课程发布 | 状态机、权限 | PG 持久化、Feign | 教师发布→学生可见 | 越权测试 |
| 资源访问 | 授权规则 | 对象存储适配器 | 学生可下载 | 文件安全 |
| 考试提交 | 幂等、判分 | PG/MQ 事务 | 开始→提交→成绩 | 并发提交 |
| 学习画像 | 事件幂等 | RabbitMQ 消费 | 答卷后出现错题 | 消息堆积 |
| AI 问答 | 权限过滤、配额 | 向量库/模型 fake | 有来源的回答 | 注入、成本限额 |

覆盖率不应只追数字。优先保证认证、授权、状态机、金额/成绩类计算、幂等和数据迁移这类高风险逻辑被覆盖。

## 7. 发布门禁与 Definition of Done

一个功能只有同时满足以下条件才可合并：

- [ ] 需求、权限、异常和验收条件已确认。
- [ ] OpenAPI、请求/响应 DTO 和错误码已更新。
- [ ] 数据库迁移、索引、历史数据兼容和回滚说明已评审。
- [ ] 完成参数校验、数据权限、事务、幂等、审计和日志。
- [ ] 单测与集成测试通过；核心流程有 E2E 回归。
- [ ] 指标与告警（如适用）已增加。
- [ ] 无高危依赖漏洞、无密钥泄露、无阻断静态扫描问题。
- [ ] 已在测试环境演示，PR 包含发布/回滚说明。

## 8. 风险与决策

| 风险 | 影响 | 决策 |
|---|---|---|
| 过早微服务化 | 联调、部署、排障成本高 | 暂保留现有服务，但新增功能不继续随意拆服务；先收口契约、观测和测试 |
| 考试高并发 | 重复答卷、成绩错误 | 幂等键、唯一约束、乐观锁、服务器时间、压测 |
| MQ 最终一致性 | 学习画像延迟或丢失 | Outbox、幂等、DLQ、重放能力 |
| 外部 AI/云服务不可用 | 核心体验被拖垮 | 超时、限流、熔断、开关、异步、降级 |
| 教育数据隐私 | 合规与用户信任风险 | 最小权限、脱敏、审计、保留期、密钥管理 |
| PostgreSQL 初始化与迁移分散 | 环境漂移 | 统一 Flyway 迁移策略，Compose 初始化只用于首次开发环境 |

## 9. 第一个执行 Sprint（可立即开始）

**Sprint 目标：完成 P0 基线收口，时间 1 周。**

1. 建立错误码表、异常响应和 traceId 规范。
2. 列出网关路由和所有匿名接口，确认 JWT 校验与用户信息透传。
3. 修复 Feign fallback 的 `null` 语义，统一超时与服务不可用响应。
4. 为登录、当前用户、课程发布、考试提交分别添加一条集成测试。
5. 补充知识点归属教师鉴权。
6. 增加 CI：Maven 构建、测试、格式检查、依赖漏洞扫描。
7. 输出一次测试环境冒烟报告：前端 → 网关 → 服务 → PG/Redis/MQ。

Sprint 完成后，才进入课程/资源闭环完善；没有这层基线，继续增加功能只会放大未来返工。
