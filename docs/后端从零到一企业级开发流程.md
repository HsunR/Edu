# 后端从零到一企业级开发流程

> 适用场景：从空仓库开始建设一个智慧教育平台后端。目标不是一次性堆出很多微服务，而是以可验证、可交付、可运维的方式逐步交付业务价值。

## 0. 总原则

1. **先业务闭环，后技术复杂度。** 先用模块化单体验证核心流程，再按真实边界拆分服务；不要为“微服务”而微服务。
2. **接口和数据是契约。** 任何跨前后端、跨服务、跨团队协作，先确定 API 契约、数据所有权和失败语义。
3. **每个阶段都应可运行。** 不接受“等全部功能完成再联调”。每个迭代必须能部署、演示、回滚。
4. **安全、测试、可观测性不是收尾工作。** 从第一个接口就接入统一异常、参数校验、审计日志、测试和 traceId。
5. **只通过 API 访问其他服务的数据。** 一个业务服务拥有自己的数据表和迁移脚本；禁止跨库查询、共享 Entity。

## 1. 里程碑总览

| 阶段 | 核心问题 | 主要产物 | 退出条件 |

## 2. M0：项目立项与需求澄清

### 2.1 先写一页项目定义

- 用户：学生、教师、教务管理员、平台管理员。
- 首个可用版本（MVP）：注册登录、课程与班级、章节资源、学习进度、作业或考试四选一的闭环。
- 暂不做：复杂推荐、多模型 AI、自建视频转码、跨校多租户等高成本能力。
- 北极星指标：例如“教师可在 10 分钟内完成课程创建并发布第一节内容”。

### 2.2 建立需求池

每个需求都使用统一卡片：

```text
标题：教师创建课程
用户故事：作为教师，我希望创建课程，以便组织班级教学。
前置条件：已登录且拥有 TEACHER 角色。
主流程：填写课程信息 → 保存草稿 → 发布。
异常流程：无权限、课程名重复、封面上传失败。
验收标准：发布后学生可见；未发布课程仅教师和管理员可见。
非功能要求：接口 P95 < 300ms；完整记录创建审计。
```

### 2.3 必须产出

- PRD 与范围清单（做/不做）。
- 用户故事和验收标准。
- 角色—页面—接口权限矩阵。
- 风险清单：隐私、AI 成本、数据迁移、第三方云服务、并发考试。
- 迭代计划：每个迭代 1～2 周，优先交付能被用户使用的纵向切片。

**检查点：** 产品、前端、后端共同确认关键名词和状态，例如“课程草稿/已发布/已归档”分别意味着什么。

## 3. M1：领域建模与服务边界

### 3.1 先划业务域，不先划技术模块

```text
身份与组织域：用户、角色、权限、院系、班级成员
教学内容域：课程、章节、资源、课程发布
测评域：题库、试卷、考试、答卷、成绩
学习域：学习记录、进度、错题、掌握度
知识域：知识点、知识点关系、题目/章节关联
智能服务域：资料处理、检索增强、AI 会话
```

### 3.2 数据所有权

| 域 | 数据拥有者 | 可以引用但不拥有的数据 |
|---|---|---|
| 用户 | 用户服务 | 无 |
| 课程 | 课程服务 | 教师 ID、学生 ID |
| 测评 | 考试服务 | 课程 ID、知识点 ID、用户 ID |
| 学习 | 学习服务 | 课程/章节/考试/知识点 ID |
| 资源 | 资源服务 | 上传者 ID、关联业务 ID |

跨域只保存对方的 ID 或快照字段；需要实时数据时调用对方公开 API。禁止让课程服务直接修改用户表，也禁止共享数据库事务。

### 3.3 事件设计

先列出关键事件，再决定是否需要 MQ：

- `CoursePublished`：通知学生、建立搜索索引。
- `ExamSubmitted`：异步判分、更新学习画像。
- `LearningProgressUpdated`：汇总学习统计。
- `ResourceUploaded`：转码或资料解析。

事件必须包含：事件 ID、发生时间、聚合 ID、操作者 ID、版本号；消费者必须幂等。

### 3.4 必须产出

- 领域名词表。
- 核心流程时序图。
- 服务边界和数据所有权图。
- 状态机：课程、资源、考试、答卷等所有有状态对象。
- 事件清单与同步/异步决策记录（ADR）。

## 4. M2：架构与技术方案

### 4.1 推荐演进策略

第一阶段采用**模块化单体**：一个 Spring Boot 应用，按领域分包，单数据库但严格分 schema/模块；使用接口隔离，不直接互相依赖实现。

当出现以下信号再拆微服务：独立部署频繁、团队明确按域负责、某域的容量模型明显不同、跨域边界稳定、监控和发布能力已具备。拆分顺序通常为：用户认证 → 资源 → 课程 → 考试 → 学习 → AI。

### 4.2 分层约定

```text
api/            Controller、Request/Response DTO、OpenAPI 定义
application/    用例编排、事务边界、命令/查询
domain/         实体、值对象、领域服务、领域事件、仓储接口
infrastructure/ Mapper/JPA、MQ、缓存、第三方 SDK、仓储实现
```

- Controller 只做协议转换、校验和调用应用服务。
- 应用服务负责用例编排和事务；不要把业务规则写进 Controller 或 Mapper。
- Entity 不直接暴露给外部；请求 DTO、响应 DTO、持久化对象分开。
- 读多写少场景可使用 CQRS 思想，但不要一开始就引入两套复杂存储。

### 4.3 基础技术选型

- Java 21 + Spring Boot 3.x。
- PostgreSQL + Flyway；Redis 用于缓存、会话、限流和分布式锁。
- OpenAPI/Knife4j 维护接口文档。
- RabbitMQ 或 Kafka 处理异步事件；先选一种并规范重试、死信和幂等。
- Docker Compose 供本地开发；Kubernetes 或目标云平台供生产。
- Micrometer + Prometheus + Grafana + 日志平台（ELK/Loki）做可观测性。

### 4.4 必须产出

- C4 架构图（系统上下文、容器、组件）。
- ADR：关键决策及取舍，如为何选择 PostgreSQL、何时拆服务。
- API 规范、错误码规范、分页规范、时间/时区规范。
- 数据库建模规范、索引规则、迁移规则、软删除策略。
- 安全方案：认证、授权、密钥、脱敏、审计、数据保留期。

## 5. M3：工程底座（先做再开发业务）

### 5.1 仓库与分支

```text
main                  随时可发布
develop（可选）        集成分支
feature/<ticket>-xxx  功能分支
fix/<ticket>-xxx      缺陷分支
release/<version>     发布准备（规模较大时）
```

- 一个 Pull Request 只处理一个明确目标。
- PR 必须关联需求/缺陷、包含测试说明和回滚说明。
- 不提交密码、Token、生产配置和真实用户数据。

### 5.2 最小工程能力清单

- 统一响应、统一异常处理、业务错误码。
- Bean Validation 参数校验；全局时区和 JSON 序列化配置。
- traceId/MDC、结构化日志、全局审计日志。
- 健康检查、就绪检查、版本信息接口。
- OpenAPI 文档、接口鉴权注解。
- Dockerfile、Docker Compose、`.env.example`。
- Checkstyle/Spotless、静态扫描、依赖漏洞扫描。
- CI：编译、单测、静态检查、镜像构建。

### 5.3 数据库从第一天开始版本化

```text
db/migration/
  V1__init_user.sql
  V2__create_course.sql
  V3__add_course_status_index.sql
```

规则：迁移脚本只追加、不修改已发布版本；每一张业务表必须明确主键、非空约束、唯一约束、索引、创建/更新时间、创建/更新人和乐观锁策略。

**检查点：** 新成员按 README 可在 30 分钟内启动，执行测试，并访问 API 文档。

## 6. M4：第一条完整业务切片——身份与权限

开发顺序：

1. 用户、角色、权限、角色权限关系的数据模型和迁移脚本。
2. 注册、登录、退出、刷新 Token、获取当前用户接口。
3. 密码采用强哈希（BCrypt/Argon2），验证码和登录失败限流。
4. JWT 或 OIDC 身份认证；网关/安全过滤器验证身份。
5. RBAC 到接口；再加入“仅本人/所属班级/课程教师”的数据权限。
6. 登录、授权失败、敏感操作写审计日志。
7. 单测、集成测试、越权测试和接口联调。

验收场景：未登录不能访问受保护资源；学生不能修改课程；教师不能修改其他教师课程；管理员可按授权范围管理。

## 7. M5～M7：按闭环交付业务

### 7.1 迭代一：课程与班级

功能：课程分类、课程草稿/发布、班级、成员管理、章节排序。

关键点：课程状态机；教师身份校验；排序并发控制；课程删除后的资源与考试处理策略。

### 7.2 迭代二：资源与学习

功能：文件上传、资源元数据、章节关联、学生访问、学习进度。

关键点：对象存储使用预签名 URL；上传完成回调与文件扫描异步化；资源访问必须鉴权；大文件不经过业务服务转发。

### 7.3 迭代三：知识点、题库与考试

功能：知识点树、题目、组卷、发布考试、提交答卷、判分、成绩。

关键点：考试/答卷状态机；提交接口幂等；客观题同步判分、复杂题异步判分；保存试卷快照，避免题目修改影响历史成绩。

### 7.4 迭代四：学习反馈

功能：错题本、掌握度、学习画像、课程统计。

关键点：把“答卷提交、视频进度变化”等转为事件；消费端可重试且幂等；统计允许最终一致，但原始记录必须可追溯。

### 7.5 迭代五：AI 助教

功能：资料解析、向量检索、对话、课程问答。

关键点：资料解析进入异步队列；模型调用设置超时、限流、预算和降级；回答需标注资料来源；不将密钥和个人敏感数据传入提示词；记录必要审计而不记录敏感明文。

每个迭代的固定产物：需求卡、OpenAPI、迁移脚本、实现、测试、监控指标、变更说明、演示脚本。

## 8. M8：测试与质量门禁

| 层级 | 测什么 | 目标 |
|---|---|---|
| 单元测试 | 领域规则、状态机、权限判断 | 快速、稳定、覆盖核心规则 |
| 集成测试 | Controller、数据库、缓存、MQ 适配 | 验证真实组件协作 |
| 契约测试 | 前后端/服务间 API | 防止接口悄悄破坏 |
| E2E 测试 | 登录到学习/考试的主链路 | 验证用户真正可用 |
| 性能测试 | 登录、选课、考试提交等热点 | 得到容量和瓶颈结论 |
| 安全测试 | 越权、注入、文件上传、Token | 覆盖 OWASP 高风险项 |

合并门禁建议：编译成功、单测通过、核心模块覆盖率达标、静态扫描无阻断问题、依赖无高危漏洞、数据库迁移可在空库执行。

## 9. M9：发布、运维与事故处理

### 9.1 CI/CD 流水线

```text
提交代码
→ 格式/静态检查
→ 单元与集成测试
→ 构建制品与镜像
→ 安全扫描
→ 部署测试环境
→ 自动冒烟/E2E
→ 人工审批
→ 灰度发布生产
→ 监控验证
→ 全量发布或自动回滚
```

### 9.2 最低生产标准

- 配置与代码分离；密钥使用 Secret 管理。
- 容器设置 CPU/内存限制、健康探针和优雅停机。
- 数据库有备份、恢复演练和迁移回滚预案。
- 关键接口具有限流、超时、熔断和告警。
- 日志可按 traceId 查询；核心指标有仪表盘：QPS、P95/P99、错误率、JVM、连接池、队列积压。
- 每个服务有 Runbook：启动、排障、扩容、回滚、常见告警处理。

## 10. 每个需求的 Definition of Done

- [ ] 需求验收条件明确，权限和异常流程已确认。
- [ ] API 已评审并更新 OpenAPI；请求/响应不泄露内部实体。
- [ ] 数据库迁移脚本、索引和回滚方案已准备。
- [ ] 实现满足参数校验、权限控制、事务边界、幂等和审计要求。
- [ ] 单测、集成测试、必要的契约/E2E 测试通过。
- [ ] 日志、指标、告警或仪表盘已补充。
- [ ] 前后端联调通过，发布与回滚说明已写入 PR。
- [ ] 代码评审完成，无阻断安全问题。

## 12. 第一天就做什么

1. 创建空仓库，写 README、PRD、领域名词表和 `.env.example`。
2. 用 Docker Compose 启动 PostgreSQL、Redis、MQ、观测基础设施。
3. 创建单体 Spring Boot 工程，接入 Flyway、OpenAPI、统一异常、日志、健康检查和测试框架。
4. 实现 `用户注册 → 登录 → 获取当前用户 → 权限校验` 的最小纵向切片。
5. 为这条切片写迁移脚本、单测、集成测试和一条 E2E 冒烟测试。
6. 只有这条链路稳定后，才开始课程域。

> 判断是否可以进入下一阶段的唯一标准：当前阶段的退出条件已验证，而不是“代码看起来写完了”。
