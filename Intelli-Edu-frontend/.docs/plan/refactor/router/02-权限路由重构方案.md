# 权限路由重构方案

## 一、当前权限系统问题

### 1.1 问题清单

| # | 问题 | 严重程度 | 位置 |
|---|------|---------|------|
| 1 | `permissionStore.generateRoutes()` 不做权限过滤 | 🔴 | `stores/permission.ts` |
| 2 | `usePermission().hasPermission()` 永远返回 `true` | 🔴 | `composables/usePermission.ts` |
| 3 | `v-hasRole` 指令引用 `useUserStore().roles`（不存在） | 🔴 | `directives/permission.ts` |
| 4 | `v-hasPermi` 指令引用 `useUserStore().permissions`（不存在） | 🔴 | `directives/permission.ts` |
| 5 | `dynamic.ts` 的 `meta.permissions` 定义了但从未被消费 | 🟡 | `router/routes/dynamic.ts` |
| 6 | `permissionStore` 维护 5 个路由列表，其中 `routes` 和 `defaultRoutes` 完全重复 | 🟡 | `stores/permission.ts` |
| 7 | 路由守卫中 `generateRoutes()` 不传参数，无法根据角色过滤 | 🟡 | `router/guards.ts` |
| 8 | 登出时未清除动态路由和 permissionStore 状态 | 🟡 | `stores/user.ts` |

### 1.2 问题根源

项目使用**角色模型**（`UserType: Student | Teacher | Admin`），但代码中混用了两套权限体系：

```
体系 A（实际在用）: UserType 枚举 → userStore.isStudent / isTeacher / isAdmin
体系 B（从未生效）: roles[] + permissions[] → 从后端获取（但后端未提供）
```

**结论**：应统一使用体系 A（角色模型），删除体系 B 的残留代码。

## 二、权限模型设计

### 2.1 角色与路由映射

| 角色 | 可见路由 |
|------|---------|
| **Student** | 课程浏览、我学的课（含全部子页面）、资源管理、设置、个人中心 |
| **Teacher** | 课程浏览、我学的课、我教的课（含全部子页面）、资源管理、设置、个人中心 |
| **Admin** | 全部路由（含系统管理） |

### 2.2 路由 meta.roles 规则

```typescript
// 无 roles 字段 → 所有登录用户可见
meta: { title: '课程浏览', icon: 'dashboard' }

// 有 roles 字段 → 仅指定角色可见
meta: { title: '我教的课', roles: [UserType.Teacher, UserType.Admin] }
meta: { title: '系统管理', roles: [UserType.Admin] }
```

### 2.3 权限判断流程

```
路由 meta.roles 存在？
├── 否 → 所有登录用户可访问
└── 是 → 用户 userType 在 roles 中？
    ├── 是 → 可访问
    └── 否 → 不可访问（不注册路由 + 不显示菜单）
```

## 三、permissionStore 重写

### 3.1 当前代码问题

```typescript
// 当前：5 个路由列表，2 个完全重复
const routes = ref<RouteRecordRaw[]>([])           // constantRoutes + addRoutes
const addRoutes = ref<RouteRecordRaw[]>([])         // 动态添加的路由
const defaultRoutes = ref<RouteRecordRaw[]>([])     // constantRoutes + addRoutes（重复！）
const topbarRouters = ref<RouteRecordRaw[]>([])     // 顶部菜单
const sidebarRouters = ref<RouteRecordRaw[]>([])    // 侧边栏菜单

// generateRoutes 不做过滤
function generateRoutes() {
  addRoutes.value = dynamicRoutes
  routes.value = [...constantRoutes, ...dynamicRoutes]
  // topbarRouters 和 sidebarRouters 完全相同
  setSidebarRouters(routes.value)
  setDefaultRoutes(routes.value)
  setTopbarRoutes(routes.value)
  isRoutesGenerated.value = true
  dynamicRoutes.forEach((route) => router.addRoute(route))
  return dynamicRoutes
}
```

### 3.2 重写后的代码

```typescript
import { defineStore } from 'pinia'
import { ref } from 'vue'
import type { RouteRecordRaw } from 'vue-router'
import router, { constantRoutes } from '@/router'
import { dynamicRoutes } from '@/router/routes/modules'
import { useUserStore } from '@/stores/user'
import type { UserType } from '@/types/enums'

function filterRoutes(routes: RouteRecordRaw[], userType: UserType): RouteRecordRaw[] {
  return routes
    .filter((route) => {
      const roles = route.meta?.roles
      if (!roles) return true
      return roles.includes(userType)
    })
    .map((route) => {
      if (route.children) {
        const filteredChildren = filterRoutes(route.children, userType)
        return { ...route, children: filteredChildren }
      }
      return route
    })
    .filter((route) => {
      if (route.children && route.children.length === 0) {
        return false
      }
      return true
    })
}

export const usePermissionStore = defineStore('permission', () => {
  const routes = ref<RouteRecordRaw[]>([])
  const addRoutes = ref<RouteRecordRaw[]>([])
  const sidebarRouters = ref<RouteRecordRaw[]>([])
  const isRoutesGenerated = ref(false)

  function generateRoutes() {
    const userStore = useUserStore()
    const userType = userStore.userType

    if (!userType) {
      console.warn('[PermissionStore] generateRoutes called without userType')
      return []
    }

    const filteredRoutes = filterRoutes(dynamicRoutes, userType)

    addRoutes.value = filteredRoutes
    routes.value = [...constantRoutes, ...filteredRoutes]
    sidebarRouters.value = routes.value
    isRoutesGenerated.value = true

    filteredRoutes.forEach((route) => router.addRoute(route))

    return filteredRoutes
  }

  function setSidebarRouters(routeList: RouteRecordRaw[]) {
    sidebarRouters.value = routeList
  }

  function resetRoutes() {
    addRoutes.value.forEach((route) => {
      if (route.name) {
        router.removeRoute(route.name)
      }
    })
    addRoutes.value = []
    routes.value = [...constantRoutes]
    sidebarRouters.value = []
    isRoutesGenerated.value = false
  }

  return {
    routes,
    addRoutes,
    sidebarRouters,
    isRoutesGenerated,
    generateRoutes,
    setSidebarRouters,
    resetRoutes,
  }
})
```

### 3.3 变更说明

| 变更 | 原因 |
|------|------|
| 删除 `defaultRoutes` | 与 `routes` 完全重复 |
| 删除 `topbarRouters` | 与 `sidebarRouters` 完全重复，当前项目不使用顶部菜单模式 |
| 删除 `setDefaultRoutes()` / `setTopbarRoutes()` | 不再需要外部手动设置 |
| 保留 `setSidebarRouters()` | TopNav 顶部菜单模式需要联动更新侧边栏，直接赋值 `sidebarRouters` 会因 Pinia 严格模式报错 |
| 新增 `filterRoutes()` | 根据用户角色过滤路由 |
| 新增 `resetRoutes()` | 登出时清除动态路由 |
| `generateRoutes()` 内部获取 userType | 不再需要外部传参 |

### 3.4 filterRoutes 递归过滤逻辑

```
filterRoutes(dynamicRoutes, UserType.Student)
  ├── / (Layout)
  │   ├── /index (课程浏览) → 无 roles → ✅ 保留
  │   ├── /course/learning (我学的课) → roles: [UserType.Student, UserType.Teacher, UserType.Admin] → ✅ 保留
  │   ├── /course/teaching (我教的课) → roles: [UserType.Teacher, UserType.Admin] → ❌ 过滤
  │   └── ...其他子路由递归过滤
  ├── /system (系统管理) → roles: [UserType.Admin] → ❌ 过滤
  ├── /resource (资源管理) → 无 roles → ✅ 保留
  └── /setting (设置) → 无 roles → ✅ 保留
```

## 四、路由守卫重写

### 4.1 `src/router/guards.ts`

```typescript
import router from './index'
import { ElMessage } from 'element-plus'
import NProgress from 'nprogress'
import 'nprogress/nprogress.css'
import { getToken } from '@/utils/auth'
import { useUserStore } from '@/stores/user'
import { usePermissionStore } from '@/stores/permission'

NProgress.configure({ showSpinner: false })

const whiteList = ['/login', '/register', '/401']

router.beforeEach(async (to, _from, next) => {
  NProgress.start()

  const token = getToken()

  if (token) {
    if (to.path === '/login') {
      next({ path: '/' })
      NProgress.done()
    } else {
      const userStore = useUserStore()
      if (userStore.userInfo) {
        if (to.matched.length === 0) {
          next('/401')
          NProgress.done()
        } else {
          next()
        }
      } else {
        try {
          await userStore.fetchUserInfo()
          const permissionStore = usePermissionStore()
          if (!permissionStore.isRoutesGenerated) {
            permissionStore.generateRoutes()
          }
          next({ ...to, replace: true })
        } catch {
          await userStore.logout()
          ElMessage.error('获取用户信息失败，请重新登录')
          next(`/login?redirect=${to.fullPath}`)
          NProgress.done()
        }
      }
    }
  } else {
    if (whiteList.includes(to.path)) {
      next()
    } else {
      next(`/login?redirect=${to.fullPath}`)
      NProgress.done()
    }
  }
})

router.afterEach(() => {
  NProgress.done()
})
```

### 4.2 变更说明

| 变更 | 原因 |
|------|------|
| 白名单添加 `/401` | 无权限页面本身无需登录 |
| 新增 `to.matched.length === 0` 检查 | 动态路由未注册时匹配为空，引导到 401 页面 |
| catch 中不再单独调用 `resetRoutes()` | `userStore.logout()` 内部已调用，避免重复 |

## 五、usePermission 组合函数重写

### 5.1 当前代码

```typescript
export function usePermission() {
  const userStore = useUserStore()

  function hasRole(role: string | string[]): boolean {
    const roles = Array.isArray(role) ? role : [role]
    return roles.includes(userStore.userInfo?.type || '')
  }

  function hasPermission(_permission: string | string[]): boolean {
    return true  // ← 永远返回 true
  }

  function hasRoleOr(roles: string[]): boolean {
    return roles.some(role => hasRole(role))
  }

  function hasPermissionOr(permissions: string[]): boolean {
    return permissions.some(p => hasPermission(p))
  }

  return { hasRole, hasPermission, hasRoleOr, hasPermissionOr }
}
```

### 5.2 重写后

```typescript
import { useUserStore } from '@/stores'
import { UserType } from '@/types/enums'

export function usePermission() {
  const userStore = useUserStore()

  function hasRole(role: UserType | UserType[]): boolean {
    const roles = Array.isArray(role) ? role : [role]
    const currentType = userStore.userType
    if (!currentType) return false
    return roles.includes(currentType)
  }

  function hasAnyRole(...roles: UserType[]): boolean {
    return roles.some((role) => hasRole(role))
  }

  function isAdmin(): boolean {
    return userStore.isAdmin
  }

  function isTeacher(): boolean {
    return userStore.isTeacher
  }

  function isStudent(): boolean {
    return userStore.isStudent
  }

  return { hasRole, hasAnyRole, isAdmin, isTeacher, isStudent }
}
```

### 5.3 变更说明

| 变更 | 原因 |
|------|------|
| 删除 `hasPermission()` | 项目不使用细粒度权限模型，此函数无意义 |
| 删除 `hasPermissionOr()` | 同上 |
| 删除 `hasRoleOr()` | 改为更语义化的 `hasAnyRole()` |
| 参数类型 `string` → `UserType` | 类型安全 |
| 新增 `isAdmin()` / `isTeacher()` / `isStudent()` | 直接代理 userStore 的 computed，使用更便捷 |

## 六、权限指令重写

### 6.1 当前代码（有 Bug）

```typescript
// 引用了不存在的属性
const roles = useUserStore().roles           // ❌ userStore 无 roles
const permissions = useUserStore().permissions  // ❌ userStore 无 permissions
```

### 6.2 重写后

```typescript
import type { App, Directive, DirectiveBinding } from 'vue'
import { useUserStore } from '@/stores/user'
import { UserType } from '@/types/enums'

function hasRole(el: HTMLElement, binding: DirectiveBinding<UserType | UserType[]>) {
  const userStore = useUserStore()
  const requiredRoles = Array.isArray(binding.value) ? binding.value : [binding.value]

  if (requiredRoles.length === 0) {
    throw new Error('v-hasRole 需要指定角色')
  }

  const currentType = userStore.userType
  if (!currentType) return

  const hasAccess = requiredRoles.includes(currentType)
  if (!hasAccess) {
    el.parentNode?.removeChild(el)
  }
}

export function setupPermissionDirectives(app: App) {
  app.directive('hasRole', hasRole as Directive)
}
```

### 6.3 变更说明

| 变更 | 原因 |
|------|------|
| 删除 `v-hasPermi` 指令 | 项目不使用细粒度权限模型 |
| 修复 `useUserStore().roles` → `useUserStore().userType` | 修复运行时错误 |
| 参数类型 `any` → `UserType \| UserType[]` | 类型安全 |
| 简化逻辑 | 只需判断 userType 是否在指定角色列表中 |

### 6.4 使用示例

```html
<!-- 仅管理员可见 -->
<el-menu-item v-hasRole="UserType.Admin">系统管理</el-menu-item>

<!-- 教师和管理员可见 -->
<div v-has-role="[UserType.Teacher, UserType.Admin]">我教的课</div>
```

## 七、userStore 适配

### 7.1 登出时清除路由状态

```typescript
// stores/user.ts
import { usePermissionStore } from '@/stores/permission'

async function logout() {
  try {
    await logoutApi()
  } finally {
    token.value = ''
    refreshToken.value = ''
    userInfo.value = null
    removeToken()
    removeRefreshToken()

    usePermissionStore().resetRoutes()
  }
}
```

> **关于循环依赖**：`user.ts` 导入 `permission.ts`，`permission.ts` 也导入 `user.ts`。在 Pinia 中这是安全的，因为 `useXxxStore()` 在函数内部调用（非模块顶层），store 实例是懒创建的。两个模块加载时不会立即执行 store 工厂函数，只有调用时才会创建实例，因此不会产生循环依赖问题。

### 7.2 不修改的部分

`userStore` 的现有接口（`userType`、`isStudent`、`isTeacher`、`isAdmin`）保持不变，这些是权限判断的基础。

## 九、权限模型总结

### 重构前

```
路由定义 → meta.permissions (从未消费)
路由生成 → 不过滤，全量注册
权限判断 → hasPermission() 永远 true
权限指令 → 引用不存在的属性，运行报错
```

### 重构后

```
路由定义 → meta.roles: UserType[] (类型安全)
路由生成 → filterRoutes() 按角色过滤后注册
权限判断 → hasRole(userType) / isAdmin() / isTeacher() / isStudent()
权限指令 → v-hasRole="UserType.Admin" (正确工作)
```
