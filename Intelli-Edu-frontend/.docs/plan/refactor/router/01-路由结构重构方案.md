# 路由结构重构方案

## 一、重构核心：路由分类修正

### 1.1 分类原则

| 分类 | 定义 | 注册时机 | 示例 |
|------|------|---------|------|
| **静态路由** (constant) | 无需登录即可访问的页面 | 应用启动时 | 登录、注册、404、401 |
| **动态路由** (dynamic) | 需要登录后才可访问的页面 | 登录后通过 `router.addRoute()` 注册 | 课程、系统管理、资源管理 |

### 1.2 当前 vs 目标分类

```
当前（错误）:
  constantRoutes = [基础页面, 首页, 个人中心]
  courseRoutes   = [课程, 资源, 设置]          ← 启动时注册，无需登录
  systemRoutes   = [系统管理]                   ← 启动时注册，无需登录
  dynamicRoutes  = [分配角色, 分配用户]          ← 登录后注册

目标（正确）:
  constantRoutes = [基础页面]                   ← 启动时注册
  dynamicRoutes  = [首页, 个人中心, 课程, 系统管理, 资源, 设置, 分配角色, 分配用户]  ← 登录后注册
```

## 二、目录结构变更

### 2.1 变更对比

```
当前:
src/router/routes/
├── constant.ts      # 混入了首页和个人中心
├── course.ts        # 混入了资源管理和设置
├── system.ts        # 系统管理
└── dynamic.ts       # 仅 2 个权限子页面

目标:
src/router/routes/
├── constant.ts              # 纯静态路由（登录、错误页等）
└── modules/                 # 动态路由模块
    ├── course.ts            # 课程模块（学习 + 教学）
    ├── system.ts            # 系统管理模块（含权限分配子页面）
    └── resource.ts          # 资源管理 + 设置
```

### 2.2 删除文件

| 文件 | 原因 |
|------|------|
| `src/router/routes/dynamic.ts` | 内容合并到 `modules/system.ts`，不再单独存在 |

### 2.3 新增文件

| 文件 | 内容 |
|------|------|
| `src/router/routes/modules/course.ts` | 课程相关动态路由 |
| `src/router/routes/modules/system.ts` | 系统管理 + 权限分配动态路由 |
| `src/router/routes/modules/resource.ts` | 资源管理 + 设置动态路由 |
| `src/router/routes/modules/index.ts` | 聚合导出所有模块 |


**变更说明**：
- 移除 `permissions?: string[]`（项目使用角色模型而非细粒度权限模型）
- `roles` 类型从 `string[]` 改为 `UserType[]`，类型安全
- `import type { UserType }` 替代原 `import 'vue-router'`（`import type` 同样使文件成为模块，确保 `declare module` 是模块增强而非环境声明）

---

## 六、路径变更的兼容策略

### 方案 A：一次性全量替换（推荐）

使用全局搜索替换，一次性更新所有 `router.push()` 和 `router.replace()` 调用。

**优点**：干净彻底，无遗留问题
**缺点**：变更量大，需要仔细测试

### 方案 B：渐进式迁移

在 `guards.ts` 中添加旧路径重定向：

```typescript
const LEGACY_PATH_REDIRECTS: Record<string, string> = {
  '/course/LearningCourses': '/course/learning',
  '/course/TeachingCourses': '/course/teaching',
  // ...
}

router.beforeEach((to, _from, next) => {
  const redirect = LEGACY_PATH_REDIRECTS[to.path]
  if (redirect) {
    next({ path: redirect, replace: true })
    return
  }
  // ... 原有守卫逻辑
})
```

**优点**：旧链接不会 404
**缺点**：需要维护映射表，最终仍需清理

### 推荐：方案 A + 保留重定向映射作为兜底

先全量替换，再在 `guards.ts` 中保留重定向映射作为兜底处理（如浏览器书签、外部链接等场景）。
