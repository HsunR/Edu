## 三、回滚方案

如果重构后出现严重问题，可按以下步骤回滚：

1. 恢复 `src/router/routes/constant.ts`（含 `/index` 和 `/user/profile`）
2. 恢复 `src/router/index.ts`（`routes: [...constantRoutes, ...courseRoutes, ...systemRoutes]`）
3. 恢复 `src/router/routes/course.ts` 和 `src/router/routes/system.ts`
4. 恢复 `src/router/routes/dynamic.ts`
5. 删除 `src/router/routes/modules/` 目录
6. 恢复 `src/stores/permission.ts`
7. 恢复 `src/router/guards.ts`

> 建议在重构前创建 Git 分支：`git checkout -b refactor/router-permission`

## 四、风险点

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 路径变更导致书签失效 | 用户收藏的旧链接 404 | 在 guards.ts 中添加旧路径重定向映射 |
| 路由 name 变更导致 `router.push({ name })` 失效 | 页面跳转失败 | 全局搜索 `name:` 引用并更新 |
| `filterRoutes` 过滤逻辑遗漏 | 某些路由不应显示却显示了 | 逐角色测试验证清单 |
| `v-hasRole` 指令在 SSR 场景下报错 | 服务端渲染失败 | 当前项目为 SPA，无此风险 |
| 登出后路由未完全清除 | 切换账号后看到上一个角色的菜单 | `resetRoutes()` 遍历 `router.removeRoute()`，所有顶层路由必须有 `name` |
| TopNav 直接赋值 `sidebarRouters` | Pinia 严格模式下报错 | 改用 `setSidebarRouters()` 方法 |
| Breadcrumb/TagsView 硬编码 `/index` | 路径变更后面包屑/标签页异常 | 全局搜索 `/index` 硬编码并更新 |
| `meta.roles` 使用字符串而非枚举 | TypeScript 编译报错 | 统一使用 `UserType.Student` 等枚举值 |
